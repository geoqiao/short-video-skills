# 用代码做短视频

画面只由时间决定：页面暴露 `window.render(t)`，给它一个秒数，它画出那一刻的画面。渲染脚本用无头 Chrome 逐帧调用它并截图，ffmpeg 把截图和配音合成 mp4。改画面就是改代码，重渲染即可。

这套做法的出处是 xilo 在 X 上的一篇文章（2026-09-29，https://x.com/xilo2991/status/2104912748794589515）。本 skill 在它的基础上加了配音对齐、跟着画面走的音效、镜头运镜、封面、配音核对、阅读时长检查、静帧检查，以及一套写脚本、画画面的规矩。音效、运镜和两项检查参考了 Lemo-Opuscar（github.com/lemomo-ai/lemo-opuscar，2026-10-24 版）的做法。Lemo 的“转折前留真静音”（DIRECTOR.md 第 6 节、dataviz STYLE.md）试过后不用：讲解视频旁白一直在讲，整段没声音在手机上像断音、冷场，所以转折只在开口前把音乐收低一下。

## 起步

需要 Node 20+、uv、ffmpeg 和本机的 Google Chrome。默认字体是 macOS 自带的宋体、苹方和 SF Mono；其他系统在 `brand.json` 的 `fonts` 里换成本机有的字体。

1. 把本 skill 的 `template/` 整个复制成一个新项目目录。
2. 在新目录里运行 `npm install`（只装 `playwright-core`）。
3. 改 `brand.json`：`series` 是封面左上角的系列名，`handle` 是封面和片尾的署名，`avatar` 是头像图片的相对路径（可以是 `null`），`colors` 和 `fonts` 是配色和字体。
4. 跑一遍示例：

```bash
uv run tools/voice.py demo                # 配音和时间线 -> episodes/01-demo/build/
uv run tools/asr.py demo                  # 配音核对：列出可能念错的句子
node tools/render.mjs demo --readcheck    # 阅读时长检查：列出停留太短、读不完的字
node tools/render.mjs demo --stills auto  # 每个镜头末尾出一张静帧
node tools/render.mjs demo                # 混配乐和音效，渲染整片 -> episodes/01-demo/out/video.mp4 和 cover.png
sh tools/covers.sh demo                   # 4:3 和 3:4 封面
sh tools/sheet.sh demo                    # 封面加各镜头末帧拼成联络表 build/sheet.png
```

命令里只写 slug，脚本自己找 `episodes/<期号>-<slug>/`。配音会把旁白文本发给微软的在线 TTS 服务。

## 项目结构

- `brand.json`：品牌。改这里，不改引擎。
- `src/lib.js`：绘图工具，挂在 `window.E` 上。
- `src/run.js`：时间线调度。第 0 帧是封面，停 0.3 秒后平移进第一个镜头；镜头之间默认平移，也可以硬切或推进；字幕和进度条也在这里画。`window.CUES` 逐帧走一遍，导出每个元素出场的时刻，给音效用。
- `src/stage.html`：渲染页面。
- `tools/voice.py`：逐行合成配音，用逐词时间戳定分句起点，输出 `build/voice.wav` 和 `build/timeline.js`。镜头切换对齐配乐的半拍。合成不完整会重试，三次失败就报错。
- `tools/mix.py`：从零合成配乐和音效，和人声混音，响度归一到 -14 LUFS，输出 `build/audio.wav`。由 `render.mjs` 调用。
- `tools/asr.py`：配音核对，见下面"配音核对"。
- `tools/render.mjs`：先导出音效事件并混音，再四个页面并行取帧，ffmpeg 编码，30 帧每秒。`--audio` 只重做声音，`--readcheck` 做阅读时长检查。
- `tools/covers.sh`、`tools/cover-vertical.mjs`：4:3 横封面（16:9 封面上下补底色）和单独排版的 3:4 竖封面。
- `tools/sheet.sh`：从成片抽封面和每个镜头的末帧，拼成联络表。
- `episodes/<期号>-<slug>/`：一期一个目录，里面是 `script.json`、`shots.js`，以及生成的 `build/` 和 `out/`。

## 一期的流程

按顺序做，前一步没过不进下一步。

内容和事实由你自己准备，本 skill 从写脚本开始。

1. **脚本**：建 `episodes/<期号>-<slug>/`，写 `script.json`，期号同时写进 `cover.no`。
2. **画面**：写同目录的 `shots.js`，镜头数等于旁白行数。
3. **配音**：`uv run tools/voice.py <slug>`。改了旁白、音色、`turns`、`holds` 或封面文案都要重跑。
4. **配音核对**：`uv run tools/asr.py <slug>`，见下面"配音核对"。
5. **阅读时长检查**：`node tools/render.mjs <slug> --readcheck`，见下面"阅读时长检查"。
6. **静帧检查**：见下面"静帧检查"。
7. **成片**：`node tools/render.mjs <slug>`，再跑 `covers.sh` 和 `sheet.sh`，看一遍联络表。
8. **交付**：见本文最后一节。

调整期号时，目录名前缀和 `cover.no` 一起改，然后重跑配音和渲染。只改封面字不用重配音：改 `script.json` 的 `cover`，把 `build/timeline.js` 里的 `cover` 换成同样的内容，再跑渲染和 `covers.sh`。

## script.json

```json
{
 "title": "这个视频是代码画的",
 "cover": { "no": "01", "lines": ["这个视频", "是代码画的"], "hot": 1, "tag": "没有剪辑软件，也没有视频模型" },
 "voice": "zh-CN-YunxiNeural",
 "rate": "+6%",
 "turns": [2],
 "holds": {"1": 1.5},
 "lines": [["你看到的每一帧，", "都是代码画出来的。"], ["页面只暴露一个函数：", "给它一个时间，", "它画出那一刻的画面。"]]
}
```

- `turns`（可选）：转折镜头的编号，从 1 数。转折前是正常的句间停顿，开口前约 0.4 秒音乐收低 15 dB、不放音效（不全停）；转折开口时一声重音，画面默认硬切。
- `holds`（可选）：`{"镜头编号": 秒数}`，这个镜头旁白念完后多停几秒，给最后出现的字留阅读时间。写在最后一个镜头上就是延长片尾。

- 一行是一个镜头，行内每个分句是一个画面节拍。分句可以写成 `[念的文本, 字幕文本]`：念"百分之七十五"，显示"75%"；英文术语念不准时也用这个办法改念法。
- 封面：`lines` 两行以内，`hot` 是用主色的那一行，`tag` 是一句带具体数字或结论的钩子，`no` 是两位期号。封面标题、平台标题和第一句旁白说同一件事。

## 脚本怎么写

- 竖屏刷到的短视频，75–90 秒、8–9 个镜头比较合适。`+6%` 语速约每秒 4.8 字（含停顿），旁白约 380–430 字（中文字加英文单词）。超了先删字再配音。
- **前两秒放这一期最吸引人的东西。** 写脚本前先回答：这一期真正抓人的是哪一点？通常是一个反常识的数字、一个具体的结果，或观众正在遇到的问题。模板里旁白 0.5 秒开口（`tools/voice.py` 的 `HEAD`），到 2 秒只念得完 8–9 个字，所以第 0 个分句要短，开头几个字就是这一点；第 1 个镜头在 1.2 秒前把它做成大字，封面的 `tag` 也说这一点。这一点要用观众自己的说法，带上主题词（"推理强度别拉满"，接着才说"从 High 拉到 Max，花费 2.9 倍，分数只多 0.6 分"），然后再进正文。不铺垫、不自我介绍、不说"今天我们来聊"，不用光秃秃的"X 是什么？"，也不用"同一个 A，同一个 B"这类还没给信息的铺垫。这是从少量视频里看出的经验，按待验证处理。
- 下面几种顺序可以作为起点，按内容调整。
- 教程类：最终效果 → 一步一个镜头 → 常见的坑 → 一句话收尾。
- 产品介绍：它解决什么问题 → 两三个主要功能，一个功能一个镜头 → 怎么开始 → 一句话收尾。
- 概念讲解：结论和数字 → 旧做法或常见误解 → 问题出在哪 → 新做法 → 具体机制 → 实测或官方数据 → 一句话收尾。
- 研究发现：结论和数字 → 常见误解 → 实验怎么做的 → 结果 → 后续研究 → 原因 → 一句话收尾。
- 每期选 1–2 个转折写进 `turns`：观众以为懂了、接下来要推翻的地方（"但 token 少，不等于便宜"）。转折句本身要短，开头就是那个反转。不选普通的段落切换，转折用多了就不显得突然。
- 收尾先用一句话说清结论或给出做法，再用一个观众凭自己经验就能回答的问句（"你平时开哪一档？"），引导评论。问句和置顶评论呼应。这条也按待验证处理，看评论数有没有变化。不单独做讲局限的镜头，数据的限定条件写在数据镜头的来源脚注里。
- 不说"下一期讲""上一期讲过"，发布顺序可能调整。要呼应别的期，说"讲某某的那一期"。
- 原文给了误差范围时，落在误差内的差距说成"几乎没变"。自己推出来的数要在交付时列为弱证据。
- 口播里不出现网址，不说"去某网站看""搜索某某"（平台把这类内容算作站外导流，见 video-publish skill）。

## 画面怎么画

`shots.js` 是一个立即执行函数，最后写 `window.SHOTS = [...]`。每个镜头是 `(c, k) => {}`：

- `c` 是 1920×1080 的 Canvas 2D 上下文。
- `k.at(i, delay, dur)` 返回第 i 个分句开始 `delay` 秒后、在 `dur` 秒内从 0 到 1 的缓出进度；`k.raw` 是同样的线性进度；`k.t` 是镜头内已过的秒数，`k.d` 是这一行旁白的时长，`k.segs` 是各分句相对镜头起点的秒数。
- 绘图工具在 `window.E`：`title`（镜头标题加品牌笔画）、`txt`、`measure`、`rise`（淡入加位移）、`pop`（弹出）、`rrect`、`path`（按进度画折线）、`arrow`、`chip`（标签块）、`code`（打字机代码块）、`stroke`（品牌笔画）、`mark`（头像）、`sign`（片尾落款）、`fmt`，配色 `C`、字体 `F`。先读 `src/lib.js` 的函数签名再用。缺的工具写在自己那期的 `shots.js` 里，不要为单个镜头改 `lib.js` 和 `run.js`。

规矩：

- 每个分句都对应画面上的一个新东西，2–4 秒必须有变化。一个镜头只讲一件事，用图讲：流程箭头、数量点阵、对比条、代码块、表格，不要整屏文字。
- 左对齐、不对称。不做深色背景加居中大字，不让所有元素一起淡入，不加发光。
- 主强调色标"这一屏要看的那个数"，不代表好坏；点睛色一屏最多用一两处。
- 按手机竖持看横屏来定字号：`txt` 会把小于 56 的字号抬高（传 24 画成 34px，传 30 画成 38px），承载信息的字传入值不小于 30，来源脚注可以传 24。估宽度按抬高后的字号算，等宽字体每个字符约为字号的 0.6 倍。
- 版面边界：字幕条在 y 932 以下，一行约 30 个全角字；封面钩子句约 14 个全角字会碰到头像；镜头有 1.025 倍的缓慢推近，贴边元素留 20px 以上；传 24 的脚注一行约 48 个全角字。
- 宋体 Black 没有"÷"，"×"会画成很大的叉：运算符用苹方画，或写成"除以""倍"。200px 大标题里英文的下伸笔画会压到下一行。
- 第 0 个分句很短时，镜头开头容易空屏：把图的骨架（轴、表头、轮廓）放在第 0 个分句进场，数据跟着后面的分句出现。
- 不是实测数据画出来的图标"示意图"。从原文图表上读出来的数字，脚注写"读自原文图表"。数据镜头底部写来源脚注，只写名称（"来源：某某官方文档"），不写域名和网址。
- 每个镜头都用 `E.title` 出标题；最后一个镜头用 `E.sign` 落款。

## 运镜和转场

镜头内运镜用 `k.cam(c, moves, from)`，写在镜头函数的第一行，在画任何东西之前：

```js
// 先贴近标题，第 1 个分句后 0.2 秒开始，1.4 秒拉回全景
k.cam(c, [{ at: 1, delay: 0.2, dur: 1.4 }], { x: 850, y: 330, z: 1.15 });
// 第 1 个分句后推近到右边的代码块；第 3 个分句前 0.3 秒拉回全景
k.cam(c, [{ at: 1, delay: 1.5, dur: 1.0, x: 1380, y: 540, z: 1.45 }, { at: 3, delay: -0.3, dur: 1.0 }]);
```

`x`、`y` 是取景中心，`z` 是放大倍数，没写的回到全景（960, 540, 1）。取景不会出画布边。

转场在 `shots.js` 里写 `window.TRANSITIONS = { 3: 'push' }`：第 3 个镜头推进进场。可选 `pan`（默认，横向平移）、`cut`（硬切）、`push`（上一镜头放大淡出，下一镜头放大淡入）。`turns` 里的镜头默认 `cut`。

每期的运镜：

- 至少一次推近，推到这一屏要看的东西上。字小的代码块、表格适合推近，在手机上推近才看得清。
- 至少一次拉远，用来露出对比或全貌：先贴近一个元素，拉远时其他元素进场。
- 一个招牌镜头，用推进转场加镜头内推拉，放在讲核心机制的那一镜。
- 强调一个数时可以快速轻推：`dur` 0.4 秒，`z` 1.08–1.12。
- 版面占满全宽的镜头放大不超过 1.1 倍，否则会切掉两边的字。推近之后贴边元素的边距按放大后算，仍要留 20px 以上。
- 推近时机放在被推开的字读完之后。`--readcheck` 把被推出画面的字算作停止显示，推早了会报出来。

运镜和音效能不能提高完播率还没验证。先在一期上用，再对比 2 秒跳出率和完播率。

## 声音

配乐和音效都由 `tools/mix.py` 用 numpy 合成，没有外部素材，没有版权问题。

- 配乐：120 BPM，四个和弦循环。长音铺底贯穿全片；拨弦、轻底鼓和反拍沙沙声从第一句开口响到最后一句念完。
- 人声出现时音乐自动压低，说话时音乐比人声低约 12 dB。
- 音效跟着画面里元素出场的时刻走，每种动作一种声音：`rise` 轻"嗒"、`pop` "啵"、画线"唰"、`stroke` 马克笔、`code` 打字"哒哒"、换镜头"呼"、推进转场"呼"加低音。同一种音效相邻至少隔 0.07–0.3 秒，元素成排出场时不会响成一片。
- 开口第一句配一声轻重音。转折开口前约 0.4 秒音乐收低 15 dB（不全停），转折开口时一声重音加钟声。最后一句念完响一声钟。
- 改了画面时机，音效会跟着变，直接重渲染即可。只想调声音时跑 `node tools/render.mjs <slug> --audio`。
- 加音效后整段混音的识别相似度从 0.977 降到 0.972（一期实测），音效基本不盖人声。

## 配音核对

`uv run tools/asr.py <slug>` 把每句配音用语音识别（faster-whisper large-v3-turbo）转回文字，和脚本逐字对比。识别模型第一次运行时下载约 1.6 GB。

输出按镜头写"没问题"或"要听"，"要听"的列出句子和它在视频里的秒数；有要听的句子时退出码是 1。明细写在 `build/asr.json`。

- 同音字（识别选错了字，念法没错）自动略过。
- 多音字列出听到的读音，人判断对不对。
- 读音不同、英文词不同、多字少字都要听。
- 识别工具自己也会听错，英文产品名尤其多（如 Claude 常被听成 cloud）。所以它只挑出可疑的地方，最后由人听。
- 人听过确认没问题的念法写进项目根目录的 `asr-ok.json`：`{"Pi": ["派"]}`，以后不再报。
- 确实念错的，用分句的 `[念的文本, 字幕文本]` 改念法，重跑配音。

## 阅读时长检查

`node tools/render.mjs <slug> --readcheck` 每 0.1 秒取一次画面，记下每段字完整显示了多久，和读完需要的时间比。需要的时间 = 中文字数 ÷ 4.5 + 其他字符数 ÷ 15 + 1.5 秒，至少 1.5 秒。不够的列出镜头、秒数和那段字，有就退出码 1。

- 只算字号大于 24 的字（来源脚注不算），不透明度到 0.9 以上、整段在画面里才算显示。打字机和数字滚动的中间状态不算。
- 片尾落款这类不用读的字，在 `txt` 的选项里写 `read: false`。
- 不够的字通常出现在镜头末尾：旁白一念完就切走了。按缺的秒数给这个镜头加 `holds`，或让字早一点出场。
- 字被推近推出了画面也算停止显示，按"运镜和转场"调推近时机。

## 静帧检查

`node tools/render.mjs <slug> --stills auto` 出每个镜头的末帧；`--stills 0,t1,t2,…` 出指定秒数的帧（0 是封面）。中间帧取每行起点后约 0.4 秒和每个分句后约 1 秒，时间点从该期的 `build/timeline.js` 里读。每次 `--stills` 会清空上一批，所以分批看，或把时间点并进同一条命令。张数多时用 ffmpeg 拼成联络表，封面和末帧看原尺寸。

逐张确认：

- 文字有没有超出卡片、代码块、表格列，或者被字幕条和进度条挡住。
- 右对齐的数字和左边的标签有没有碰上；坐标轴标签和曲线标签有没有叠在一起。
