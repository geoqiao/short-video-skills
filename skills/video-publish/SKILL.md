# 发布短视频

分两段：先写文案，再填表单。文案写进该期目录的 `post.md`（结构见 `references/post-template.md`），填表单时照着它填。平台规则和依据见 `references/platform-rules.md`，发布前以投稿页为准。

## 一、写文案

文案按搜索意图写：先确认观众真的这样问、用的是哪个叫法，再让标题、封面字和描述第一句对着同一个问题。在抖音和视频号上，大部分流量来自推荐而不是搜索，这些词的主要作用是让系统把视频推给对的人。

### 先查联想词

1. 列出这条视频能回答的问题。每个问题对应一类意图：认识主角（"X 是什么""X 好用吗"）、选工具（"X 对比""哪个好"）、概念（"某术语是什么"）、怎么做（"X 怎么用"）。
2. 读联想词，确认观众真的这样搜、用哪个叫法。联想词没有搜索量，只说明有人搜。**发布当天重读一遍**，不要沿用几天前存下的结果。
   - 抖音：接上用户已登录的 Chrome（见下面"接上浏览器"），开一个 `www.douyin.com` 标签页并切过去，改 `scripts/douyin-suggest.js` 的 `SEEDS`，再 `playwright-cli -s=chrome --raw run-code --filename=scripts/douyin-suggest.js`。
   - 小红书：开一个 `www.xiaohongshu.com/explore` 标签页，改 `scripts/xhs-suggest.js` 的 `SEEDS` 后运行。每个词重载一次页面，约 6 秒一个，一次别超过 25 个词。
   - Google：`node scripts/google-suggest.mjs '[["种子词","zh-CN"],["seed","en"]]'`，不用浏览器。
   - 这三个脚本都只读。用完只关自己开的标签页。
3. 原始结果按日期存成 JSON，文案里引用文件名。
4. 主打和内容完全对口的那一类意图，写进标题、封面和描述第一句。只能部分回答的意图（例如只比了两款，却去接"哪个最好"）只放进话题，否则点进来的人会划走。联想词里反复出现、视频没回答的问题不硬接，记成新选题。

几条反复验证过的经验：

- 英文术语单独当主词经常搜不到对口内容。封面主词用中文的问法，英文放进描述和话题。
- 视频里的叫法和观众的叫法不一样时，标题、封面和旁白都跟观众（例如观众搜"上下文腐烂"，不搜"上下文腐化"）。
- 两个平台的叫法常常不同，标题用两边都出现的那个。

### 怎么写

- **标题**：观众会问的那个问题，加一个具体结论。用他们搜的叫法。没人搜的术语不进标题。标题、封面字和第一句旁白说同一件事。
- **描述**：第一句重复标题的问题并给结论和数字；再列视频讲的几件事，带上视频里出现过的实体词和数字；最后写数据来源的限定条件；用了 AI 时写上 AI 声明（例如"配音为 AI 合成"）。写给观众看，不写制作过程。
- **话题标签**：主角的准确叫法、视频里比过的对象、品类词、一个受众对口的大词。只用视频里真的讲到的词。填表时在发布页输入 `#词` 读浏览量，几百亿浏览的泛词（例如 #AI）当场换掉。抖音网页端最多 5 个，系列名交给合集，不占话题位置；视频号可以多带一两个，带上系列名。
- **置顶评论**：一个观众凭自身经验就能回答的问题，和视频结尾的问句呼应。
- **封面字**：两行以内的标题加一句带数字或结论的钩子，主词用中文问法。
- 文案、封面、口播和画面里都不出现网址和站外账号，不说"去某网站看""搜索某某"。可以引导评论、关注、看合集。
- 用了 AI 配音、AI 画面或数字人，就做 AI 声明；code-video 的配音是 AI 合成的，用它做的视频都要声明。各平台的选项名见 `references/platform-rules.md`。

## 二、填表单

各平台的选择器、坑和做法：

- 抖音创作者中心：`references/douyin.md`
- 视频号助手：`references/weixin.md`
- 小红书创作服务平台：`references/xiaohongshu.md`

### 规矩

- **不替用户发布。** 填完停在发布按钮前，等用户检查。只有用户对这一条明确说"发布"之后才点；对上一条的授权不延续到下一条。用户也可以一次授权一批（写明哪几条、立即发还是定时、各在什么时间），这时按清单逐条发，清单外的不发。
- **批量发布时，点发布前逐项核对。** 脚本读回视频、标题、描述（和文案逐字比对）、话题个数、两张封面、合集集数、声明、位置和发布时间，有一项不对就停下不点，修好再核对一遍。
- 点了发布之后，核对作品列表里出现了新作品、合集集数和期号对得上，再把发布时间记进 `post.md`。定时作品还要核对列表里显示的发布时间。
- 不修改、不删除平台上已经发布的内容，除非用户要求。
- 位置、合集、活动这类每次都可能变的项，没有定论就问用户。
- 只关自己开的标签页。标签页里有还没发布的表单时，不重载、不在这个标签页上跑别的脚本。

### 接上浏览器

需要 playwright-cli 和它配套的 Chrome 扩展，用户在 Chrome 里已登录各平台的创作者后台。

```bash
playwright-cli -s=chrome attach --extension=chrome   # 用户在扩展弹出的页面上点允许
playwright-cli -s=chrome tab-new <发布页网址>
playwright-cli -s=chrome tab-list
playwright-cli -s=chrome tab-select <序号>            # tab-new 不会切换 run-code 的目标页
playwright-cli -s=chrome --raw run-code --filename=<脚本.js>
playwright-cli -s=chrome screenshot --filename=<图.png>
```

`run-code` 的脚本是一个 `async page => { … }` 表达式，返回值会打印出来。会话断开后重新 attach，之前开的标签页会一起消失，表单要从头填。

### 通用做法

- **每个脚本开头先 `await page.bringToFront()`。** 用户同时在用 Chrome 时，发布页常被切到后台，拖放和点击会一直等到超时；超时前排队的键盘输入会在页面回到前台后补打进去，把描述弄乱。出过超时就先清空描述框再重填。
- **一步一个脚本，做完就核对。** 每步结束读一下相关区域的 `innerText` 或截一张图，确认值真的变了，再做下一步。
- **上传视频**：先试 `playwright-cli -s=chrome drop "<上传区选择器>" --path=<mp4>`。拖放不触发上传的平台，用 `scripts/` 里的注入脚本：它把文件转成 base64 写进一段 `run-code` 脚本，用 `DataTransfer` 放进 file input 并派发 `change`。扩展模式下 `setInputFiles` 和文件选择框都用不了。
- **上传封面**：先打开封面弹窗，再运行注入脚本。三个平台都要两张：4:3 横封面和 3:4 竖封面。直接用 16:9 封面会被裁掉标题。
- **下拉框和搜索框**：很多输入框只在下拉展开时可见。`fill` 和 `click` 报"element is not visible"时，先点显示当前值的那个框（必要时用 `boundingBox` 或在 `evaluate` 里取坐标再 `page.mouse.click`），等输入框出现再输入。需要触发搜索的框要逐字 `keyboard.type`，`fill` 不触发。
- **选下拉项要精确**：用完整文本匹配，或在 `evaluate` 里找 `innerText` 完全相等、且在下拉区域内可见的元素再点坐标。按部分文字过滤容易点到外层容器，选中别的项。选完读一遍当前值。
- **只在悬停时出现的按钮**：先 `page.mouse.move` 到卡片上，等半秒，再点按钮的位置。
- **英文选项**：有的平台选项显示成英文（视频号的视频标注），按页面上实际显示的文字选。

## 发布后

在抖音数据中心看"搜索词"和流量来源里的搜索占比，对照这次选的词。改过写法的视频要记下来，下次比较时才分得清是哪一处起了作用。每天的数据可以用 video-data skill 采集。

## 交付时要说明的

- 文案主打的意图、用了哪些联想词、哪些词没接以及原因。
- 每个平台填了什么：标题、话题个数、封面、合集和集数、位置、声明、热点或活动。
- 停在了哪一步，哪些项没填或和文案不一致，原因是什么。
- 如果点了发布：发布时间、作品列表核对结果、合集集数。
